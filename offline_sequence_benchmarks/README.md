# Офлайн-бенчмарки поиска последовательностей

Эта папка объединяет три эксперимента: обход синтетического графа, динамическое построение графа из HTML и подбор параметров Q-learning и генетического алгоритма, включая три гибрида. Это бенчмарки функционального покрытия на встроенных стендах. Они не запускают браузер, не обращаются к сети и не проверяют уязвимости.

## Добавление в существующий репозиторий

Распакуйте архив и скопируйте папку `offline_sequence_benchmarks/` целиком в корень репозитория. Запускайте команды из корня после того, как Python 3.10 или новее стал доступен. Установка пакетов не нужна, а существующие зависимости, исходники и настройки DAST не меняются.

```bash
python -m unittest discover -s offline_sequence_benchmarks/tests -v
python -m offline_sequence_benchmarks --profile smoke
```

Если нужен запуск в GitHub Actions, эти команды можно добавить как отдельный шаг в Python-job после checkout и настройки Python. Шаг не требует адреса приложения, токенов или запущенного стенда. В нём нет сравнения метрик между алгоритмами с порогами для CI: `smoke` проверяет работоспособность конвейера, а не качество исследовательских результатов.

```yaml
- name: Check offline sequence benchmarks
  run: |
    python -m unittest discover -s offline_sequence_benchmarks/tests -v
    python -m offline_sequence_benchmarks --profile smoke
```

## Воспроизведение экспериментов

```bash
python -m offline_sequence_benchmarks --profile full
```

По умолчанию в одном эпизоде разрешено **до 64 действий**. Это также длина генома в генетическом алгоритме; эпизод может закончиться раньше. Лимит можно задать флагом `--horizon`, например `--horizon 128`. Бюджет всего прогона от этого не меняется: 600 действий в полном HTML-бенчмарке и 1200 в полном синтетическом.

Результаты пишутся в `offline_sequence_benchmarks/output/full/` или `offline_sequence_benchmarks/output/smoke/`. Папка `output/` исключена из Git; при необходимости задайте другое место через `--output-dir`. Команды полного и быстрого запуска сохраняют результаты в отдельных подпапках. Для сравнения разных `--horizon` используйте разные `--output-dir`, иначе новый прогон перезапишет файлы того же профиля.

| Эксперимент | Что проверяет | Файлы полного прогона |
|---|---|---|
| Синтетический граф | Случайный обход, Q-learning и генетический поиск на заранее построенном графе | `sequence_search_results.csv` |
| [HTML-стенд](docs/html_fixture.md) | Извлечение ссылок и форм и пополнение графа по мере исполнения действий в памяти | `html_sequence_results.csv`, `html_sequence_graphs.json` |
| [Подбор и гибриды](docs/tuning.md) | Подбор параметров на отдельных seed, контрольные прогоны и три последовательных гибрида | `html_tuning_dev.csv`, `html_tuning_test.csv`, `html_tuning_hybrids.csv`, `html_tuning_summary.json` |

Для самостоятельного запуска конкретного эксперимента используйте `python -m offline_sequence_benchmarks.synthetic --help`, `python -m offline_sequence_benchmarks.html_fixture --help` или `python -m offline_sequence_benchmarks.tuning --help`. Семь эталонных файлов в `reference_results/` и таблицы в документации относятся к прежнему лимиту **24 действия за эпизод**. Для воспроизведения используйте Python 3.14 и команду:

```bash
python -m offline_sequence_benchmarks --profile full --horizon 24 --output-dir results-24
```

## Переменное число действий

Ген хранит число \(u\) из \([0,1)\), а не готовый индекс. Только при выполнении шага он преобразуется в ранг \(\lfloor u m\rfloor\), где \(m\) — число доступных сейчас действий. Например, \(u=0{,}72\) даёт индекс `2` при трёх действиях и индекс `7` при одиннадцати. Нет фиксированного максимума и смещения от взятия остатка по модулю; при отсутствии действий маршрут заканчивается. Мутация заменяет ген новым значением из того же интервала.

Гибриды кодируют известные префиксы по рангам действий в уже наблюдавшихся состояниях. Для этого используются записанные рёбра, без дополнительного исполнения. Чтобы префикс в этом детерминированном стенде повторял те же действия, порядок доступных действий для одного и того же состояния должен оставаться стабильным; изменение раннего шага может изменить смысл последующих генов.

Старые прогоны, в которых гены были числами `0–3`, не обязаны совпадать с новыми при тех же seed. Все три эксперимента заново выполнены с новым кодированием, а таблицы в документации обновлены.

## Граница между бенчмарком и DAST

Бенчмарки запускаются **рядом** с существующей DAST-проверкой и не передают найденные последовательности сканеру. В пакете нет HTTP-исполнителя, подключения к сканеру или параметра для внешней цели.

Для `repo-analyzer` есть отдельный [адаптер готовых артефактов](docs/dast_artifacts.md): он читает существующий ZAP JSON и необязательную запись функциональных переходов. Режим `--graph-from-trace` строит граф наблюдавшихся переходов из записи готового теста, отдельно от ZAP. Адаптер не заменяет runner `dynamic` и не меняет состав отчётов, UI или бенчмарки.
