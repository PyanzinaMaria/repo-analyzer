# Динамическое построение графа действий из HTML: небольшой бенчмарк

Бенчмарк сравнивает случайный обход, Q-learning и генетический алгоритм на офлайн-стенде «Редактор буклета». Он воспроизводит этап обхода, характерный для DAST, но измеряет только функциональное покрытие интерфейса. Сетевых запросов, браузера, JavaScript и проверок на уязвимости нет.

## Запуск

Нужен Python 3.10+ без сторонних пакетов. Выполните команду из корня репозитория, в котором находится папка `offline_sequence_benchmarks/`. Для воспроизведения таблиц ниже явно задан прежний лимит 24; если опустить флаг, лимит составит 64.

```bash
python -m offline_sequence_benchmarks.html_fixture --seeds 10 --budget 600 --horizon 24 \
  --csv html_sequence_results.csv --graph-json html_sequence_graphs.json --graph-seed 8
```

## Как появляется граф

- **Состояние:** отдельная наблюдаемая разметка HTML. На `/preview` статус текста, палитра и обложка меняют разметку и могут сделать доступной новую ссылку. Поэтому одинаковый URL не обязательно означает одинаковый узел.
- **Кандидат действия:** ссылка или форма, извлечённая из полученной разметки через `HTMLParser`. Парсер понимает только разметку стенда: ссылки, формы с фиксированными значениями и кнопки отправки.
- **Наблюдаемое ребро:** источник, выполненное действие и полученное состояние. Если действие найдено, но ещё не выполнено, его цель графу неизвестна. Начальный граф каждого прогона содержит одну страницу, четыре найденных действия и ни одного выполненного перехода.
- **Равный бюджет:** каждый запуск использует 600 исполнений действий, включая повторные шаги. Возврат к исходному состоянию между эпизодами бесплатный для всех методов. Длина эпизода ограничена 24 действиями, как в предыдущем бенчмарке.

## Что получилось

Полный эталон (93 состояния и 273 ребра) вычисляется после прогонов и не передаётся алгоритмам. Три редких состояния определены для оценки заранее: это страницы предпросмотра, которые появляются при разных сочетаниях настроек. Их минимальные глубины: 8, 11 и 11 действий.

| Метод | Состояния | Найденные действия | Выполненные рёбра | Прогоны с редким состоянием |
|---|---:|---:|---:|---:|
| Случайный обход | 63,4 | 200,3 | 140,7 | 4/10 |
| Q-learning | 49,0 | 155,7 | 105,7 | 1/10 |
| Генетический алгоритм | 62,7 | 198,1 | 139,2 | 4/10 |

Первые три числовых столбца усреднены по десяти запускам. Действие считается в контексте конкретного состояния: одна и та же кнопка в двух состояниях учитывается дважды. На этом стенде и при этих настройках ни один метод не обошёл случайный обход; результаты десяти запусков на одном стенде не устанавливают универсального превосходства.

## Как читать результаты

- **CSV:** все 30 запусков, включая первый найденный редкий предпросмотр и последовательность, которая к нему привела. Шаг первой находки отсчитывается от начала прогона, а длина последовательности от начала её эпизода.
- **JSON:** три графа для `seed=8`, по одному на метод. `nodes[].discovered_at` показывает момент обнаружения состояния и его действий, `edges[].first_used_at` показывает первое выполнение ребра, а `checkpoints` содержит размеры графа на разных шагах. В `proof_sequences` сохранены все редкие предпросмотры, достигнутые в этом прогоне, и их воспроизводимые последовательности.
