### 1. This check does not consider data:.

**[CWE-20](https://cwe.mitre.org/data/definitions/20.html) Input validation** · [`lib/index.js:31`](https://github.com/markdown-it/markdown-it/blob/f7976b25f79df1599c98787e16873d52bd0b7d05/lib/index.js#L31) · via codeql

The validateLink function blocks protocols listed in BAD_PROTOCOLS but the CodeQL rule indicates 'data:' is
not considered. Since 'data:' URLs can execute JavaScript in certain contexts (e.g., iframe src, object data),
this is an incomplete blocklist. The function is reachable from multiple markdown parsing entry points (link,
image, autolink, reference, linkify) that process user-supplied markdown.

**Flow:** User-supplied URLs in markdown links, images, and autolinks → validateLink() returning true for 'data:' scheme URLs

**Checks on the path:** trim(), toLowerCase(), colon check, BAD_PROTOCOLS blocklist

**Attacker needs / exploit idea:** Attacker provides a markdown link/image with a 'data:' URL (e.g., '![x](data:text/html,<script>alert(1)</script>)') and the application renders the output without additional sanitization

### 2. Prototype Pollution in assign utility

**[CWE-1321](https://cwe.mitre.org/data/definitions/1321.html) Prototype pollution** · [`lib/common/utils.js:18`](https://github.com/markdown-it/markdown-it/blob/f7976b25f79df1599c98787e16873d52bd0b7d05/lib/common/utils.js#L18-L34) · via LLM

The assign function copies all own enumerable properties from source objects to a target object without
filtering dangerous keys like __proto__, constructor, or prototype. Since Object.keys() returns these keys
when they are own properties (e.g., from JSON.parse('{"__proto__":{"polluted":true}}')), an attacker
controlling the options parameter can pollute Object.prototype. This affects all objects in the application
and can lead to denial of service, logic bypasses, or remote code execution depending on how polluted
properties are used downstream.

**Flow:** User-controlled options object passed to MarkdownIt constructor or set() method → MarkdownIt.prototype.set calls utils.assign(this.options, options) at lib/index.js:341 → utils.assign iterates Object.keys(source) and assigns each key to target at lib/common/utils.js:29 → If source contains __proto__, constructor, or prototype as own properties, they are copied to target's prototype

**Attacker needs / exploit idea:** Pass a malicious options object with __proto__ property to markdown-it: `const md = require('markdown-it')({ __proto__: { isAdmin: true } })` or `md.set({ __proto__: { env: { NODE_OPTIONS: '--require /tmp/evil' } } })`. The polluted prototype properties may be inherited by other objects and affect application behavior.

### 4. Incomplete URL protocol blocklist allows data: URIs

**[CWE-184](https://cwe.mitre.org/data/definitions/184.html) ** · [`lib/index.js:26`](https://github.com/markdown-it/markdown-it/blob/f7976b25f79df1599c98787e16873d52bd0b7d05/lib/index.js#L26-L35) · via LLM

The validateLink function uses a deny-list (BAD_PROTOCOLS) to reject dangerous URL schemes. The CodeQL static
analysis hint at line 31 indicates that the 'data:' protocol is not considered by this check. Since data: URIs
can contain HTML and JavaScript (e.g., data:text/html,<script>...), allowing them creates an XSS vector when
the markdown is rendered to HTML and viewed in a browser. The blocklist approach is inherently fragile; an
allow-list of safe protocols (http:, https:, mailto:, etc.) would be more secure.

**Flow:** Attacker supplies markdown containing a link with a data: URI (e.g., [x](data:text/html,<script>alert(1)</script>)) → Markdown parser extracts the URL and passes it to normalizeLink → validateLink is called to check the normalized URL → validateLink lowercases and trims the URL, then splits on ':' to extract the protocol → The protocol 'data' is not present in BAD_PROTOCOLS (or the blocklist is otherwise incomplete) → validateLink returns true, accepting the link → The link is rendered into HTML output as an <a> or <img> tag with the data: URI intact → When the rendered HTML is viewed in a browser, the data: URI executes script content

**Attacker needs / exploit idea:** Submit markdown content containing a link or image with a data: URI payload such as ![x](data:text/html,<svg/onload=alert(origin)>). The parser will accept the link because 'data' is not blocked, and the rendered HTML will execute the script when loaded in a browser.
